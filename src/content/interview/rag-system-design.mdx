## 问题

请描述如何从零设计一个生产级 RAG（检索增强生成）系统，包括架构设计、关键技术选型和性能优化策略。

## 参考答案

### 整体架构

```text
             ┌──────────┐
             │  用户查询  │
             └─────┬────┘
                   ▼
     ┌─────────────────────┐
     │  1. Query Rewriting │ ← 查询改写/扩展（可选）
     └─────────┬───────────┘
               ▼
     ┌─────────────────┐
     │ 2. Embedding    │ ← 查询向量化
     └────────┬────────┘
              ▼
     ┌─────────────────┐
     │ 3. Retrieval    │ ← 向量检索 + BM25 混合检索
     └────────┬────────┘
              ▼
     ┌─────────────────┐
     │ 4. Re-ranking   │ ← 重排序（Cross-Encoder）
     └────────┬────────┘
              ▼
     ┌─────────────────┐
     │ 5. Generation   │ ← LLM 生成回答
     └────────┬────────┘
              ▼
     ┌─────────────────┐
     │    最终回答      │
     └─────────────────┘
```

### 关键技术选型

| 组件 | 选项 | 选择依据 |
|------|------|---------|
| 嵌入模型 | text-embedding-3-small/large、BGE-M3 | 中文/多语言支持 |
| 向量数据库 | Milvus、Weaviate、Pinecone | 规模、延迟要求、是否自部署 |
| 检索策略 | 稠密+稀疏混合检索 | 提升召回率 |
| LLM | GPT-4、Claude、Qwen | 成本、性能、延迟权衡 |

### 文档处理 Pipeline

```python
class DocumentPipeline:
    def process(self, file):
        # 1. 解析：PDF/docx/txt → 纯文本
        text = self.parse(file)

        # 2. 清洗：去除页眉页脚、OCR 修正
        text = self.clean(text)

        # 3. 分块：语义分块 vs 固定大小分块
        chunks = self.semantic_chunk(text, max_size=500)

        # 4. 元数据提取：标题、层级、页码
        chunks = self.enrich_metadata(chunks)

        # 5. 嵌入：向量化
        embeddings = self.embed(chunks)

        # 6. 存储：写入向量数据库
        self.store(chunks, embeddings)
```

### 检索优化策略

1. **混合检索**：Dense（语义）+ Sparse（关键词）
2. **多路召回**：不同维度的检索策略并行召回
3. **重排序**：使用 Cross-Encoder 精排 Top-K 结果
4. **查询改写**：HyDE（假设文档嵌入）、Query2Doc

### 评估指标

| 指标 | 说明 |
|------|------|
| Recall@K | Top-K 结果中相关文档的占比 |
| MRR | 第一个相关文档排名的倒数均值 |
| NDCG | 考虑排序质量的评价指标 |
| Faithfulness | 回答是否忠实于检索到的上下文 |

### 生产环境注意事项

1. **缓存策略**：热门查询缓存，减少重复计算
2. **增量更新**：文档变更时增量更新索引
3. **多租户隔离**：不同客户的文档集合隔离
4. **限流与降级**：高峰期降级到简单搜索
5. **监控告警**：检索延迟、召回率、生成质量监控
